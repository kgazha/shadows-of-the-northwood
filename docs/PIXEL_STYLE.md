# PIXEL_STYLE — единый пиксельный канон «hand-made пиксель» (t53)

Канон пользователя 13.11: игра рисуется **ручным пиксель-артом кодом**, это
**НЕ 8-bit**: PNG32/RGBA8, полная глубина цвета; никаких ген-картинок (qwen
снесён t52), никаких квантизационных полос и системных палитр. Масштаб мира —
после t51: зум 1, герой 16 px (клетка), зум-строки и H-мультипликаты из
SCALE_CANON.md остаются источником пропорций, этот документ добавляет
**стилистику**: палитру, контур, свет, ярусность и модуль.

Лист-пример «Деревня v4» (`scratch_cm\t53_pixel\sheet_village.png`, ряды 4x и
1x) — **на вердикт пользователя до любой интеграции в игру**.

## 1. Единственный источник цвета — `pixel-rpg/scripts/pixel_palette.gd`

Все будущие волны рисуют **только** цветами `PixelPalette.RAMPS` (или
`PixelPalette.FLATS`; `SHEET` — технические цвета листов-вердиктов, не для
игры). Инструменты рисовки обязаны иметь самопроверку «чистота палитры»
(пример: `pixel-rpg/tools_art/sheet_village.gd`). Новый материал/цвет —
только вердиктом пользователя + правкой модуля.

Ramp материала = ровно 4 тона: **[LIGHT, MID, DARK, OUTLINE]**.
Свет СЗ ⇒ LIGHT — верх/лево, DARK — правый бок, OUTLINE — низ/нижние бока.

## 2. Правило контура (единый для всех спрайтов)

1. Силуэт обводится **тоном OUTLINE собственного материала** (тёмный, но
   цветной). Чистый `#000000` forbidden.
2. Контур **взвешенный**: полная линия — по нижней и нижне-боковым открытым
   граням; правая боковая открытая грань — DARK; верхняя/левая открытая грань
   — LIGHT-подсветка (1 px). Это реализовано единым прогоном `canon_pass()`
   (см. лист) и даёт ощущение одного резца у всех спрайтов.
3. Толщина контура — ровно 1 px. Никаких двойных обводок и «свечения».

## 3. Свет — один, северо-западный

* Источник света один на весь мир: сверху-слева. OPEN-грани сверху/слева
  получают LIGHT, снизу/справа — тень материала.
* Самоизлучающие материалы — исключения с внутренней логикой: FIRE (горячее
  ядро FIRE_HOT в середине/низу пламени), CRYSTAL и MOSS_GLOW (свечение из
  центра кристалла/пятна). Они не «освещают» соседей пикселями.
* Падающие тени на земле — только системные (атлас `shadow.png` +
  `atmosphere.gd`, канон-масштаб = высота/16); в самих спрайтах baked-теней
  нет.
* Блик (1–3 px LIGHT/FLAT) — один на объект, в СЗ-четверти.

## 4. Ярусность и ноги (y-sort якорь)

* **Нижний пиксельный ряд спрайта = линия ног = якорь y-sort.** Глубина
  пропа = глобальная Y его низа, актёра — его стопа (шкала V-01, t33;
  цикл mod 4800). «Слой поверх всех» запрещён.
* Нижняя кромка силуэта после `canon_pass` всегда OUTLINE — визуальное
  подтверждение ноги-ряда (самопроверка листа это сторожит).
* Актёры: YS_ACTOR_BIAS = 8; дим-контракты (крона ≥50%, проп ≥40% бокса
  16×16) — без изменений (SCALE_CANON).
* Крона — fit-оверхед: bbox на ~12% шире/ниже кластера, глубина по ноге ствола.

## 5. Модуль и пропорции

Модуль тайла **16 px**; всё считается от роста героя **H = 16 px** (зум 1,
кадр 40×22.5 клетки). Таблица SCALE_CANON.md остаётся силой; колонка v4 —
нативные размеры листа «Деревня v4» (ряд 1x = пиксель-в-пиксель экран игры).

| объект | ×H | экран px (канон) | v4 нативный спрайт |
|---|---|---|---|
| герой / NPC / мелкие мобы | 1.0 | 16 | 16-лист 1:1 (t17 сохранён) |
| громилы ярусы 1–3 | 1.4–2.0 | 23/27/32 | — |
| Гром | 2.0 | 32 | — |
| Ведьма Пепелища | 2.24 | 35.8 | — |
| изба | 2.4 | ~38 | **HUT 35×36** |
| колодец | 1.8 | 29 | **WELL 21×27** |
| костёр (тренога с котлом) | ~1.4 | 23 | **CAMPFIRE 23×23** (бокс POI 32) |
| указатель | 3.0 | 48 | **SIGN 13×45** |
| пень | 0.55 | 9 | **STUMP 11×8** |
| кластер камней | 0.75 | 12 | **STONES 15×12** |
| одиночный валун | 0.65 | 11 | **BOULDER 17×11** |
| крона рощи (ель) | 3.0 | ~48 | **PINE 29×48** |
| крона рощи (дуб, fit-оверхед) | 3.0 | ~48 | **OAK 45×44** |

Правило нарезки: **спрайт рисуется нативно в экранном размере** (1x-ряд листа
= то, что игрок видит при зуме 1); дробный fit bbox-клампом остаётся только
для легаси-монтировок до их переноса на 1:1; апскейл пиксель-арта (>1.0)
запрещён всегда.

## 6. Запреты (чек-лист ревьюера)

1. Ген-картинки (qwen и любой AI-растр) — никогда (закон 13.11).
2. 8-bit/системная палитра, квантизация, «полосы» градиентов — никогда;
   дизеринг допускается только одиночными пикселями-текстурами (<8% площади),
   не для градиентов.
3. Цвета вне `PixelPalette` — никогда; чистые #000/#FFF — никогда (FIRE_HOT —
   единственное исключение-акцент, в спрайтах игры — только у огня).
4. Больше 4 тонов на материал; контур не-материальным цветом; два источника
   света в одном спрайте.
5. «Слой поверх всех», z вне стопы, baked-пашающие тени, мягкие тени кистью.
6. Апскейл спрайтов, ресайз не-целочисленный в рантайме (кроме легаси fit до
   переноса).

## 7. Инструмент-эталон и самопроверки

`pixel-rpg/tools_art/sheet_village.gd` — шаблон инструментов новой волны:

```
Godot --headless --path pixel-rpg -s res://tools_art/sheet_village.gd -- <out.png>
```

Самопроверки (exit≠0 при провале): (1) чистота палитры — все пиксели ∈
RAMPS/FLATS; (2) нижний ряд каждого спрайта — только OUTLINE-тона; (3) СЗ-
подсветка присутствует (LIGHT в верхней половине). Все три — механическая
форма правил §1–3.

## 8. Вердикт-лист пользователя (по листу «Деревня v4»)

1. Палитра лес/деревня — ок/править (конкретные HEX)?
2. Толщина и «вес» контура, направление света — ок?
3. Размерный ряд (1x-внизу = как в игре): изба/колодец/костёр/указатель/
   пень/камни/кроны относительно героя 16 px — ок?
4. Стиль форм (рубленые срубы, лопастные кроны, ярусы ели) — ок или уходить
   в более мягкий/округлый?
5. После вердикта — волна интеграции: пропсы/кроны в `_add_prop`/GroveCanopy,
   затем аналогичные листы «пещеры v4», «Пепелище v4», «UI v4».
